# Sprinter Device Migration Guide

SPRINTER HEALTH
DEVICE MIGRATION & UPDATE GUIDE
============================================================

Build a polished, interactive, mobile-first web application called:

SPRINTER HEALTH
DEVICE MIGRATION GUIDE

Primary audience:

SPRINTERS / FIELD USERS

This application is NOT for IT technicians.

It is a simple, visual, guided experience that helps a Sprinter safely
complete required device updates, resets, and migration steps.

The user should NOT need to understand technical terminology.

The application should explain the process in plain language.

============================================================
1. CORE PURPOSE
============================================================

Sprinter Health is moving devices from an older device management system
to a newer system.

The Sprinter does NOT need to understand the technical details of the
migration.

Explain it simply:

“We are moving your Sprinter Health devices to a new system that helps
IT manage and support your devices.”

Explain WHY the user is being asked to do this.

Make the importance very clear:

IMPORTANT:

Completing these steps helps make sure your Sprinter Health devices
continue to work properly and remain ready for patient visits.

If required updates or resets are not completed, your device may
eventually have problems connecting to required services, receiving
updates, or working properly during patient visits.

If you are already having problems with your device, connectivity,
apps, or other technology, this is also a good time to tell IT.

Do not use fear-based language.

Use a calm but clear warning.

28. ACCESSIBILITY
============================================================

Design specifically for:

• ADHD
• ADD
• Dyslexia
• Low technical confidence
• Users who are stressed by device instructions

Use:

• 6th-grade reading level
• Short sentences
• One action at a time
• Large text
• Large buttons
• High contrast
• Clear icons
• Strong spacing
• Minimal jargon
• Visual examples
• Repeated orientation
• Progress indicators

Avoid:

• Paragraph-heavy pages
• Technical explanations unless requested
• Tiny instructions
• Multiple competing buttons
• Color-only warnings
